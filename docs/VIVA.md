# Viva guide

**How does real data enter the system?** Employers/placement cells import verified listing references or CSV with provenance, dates and status. Participants register and upload their own documents with consent, or the placement cell imports authorized profiles. Official ESCO/O*NET records supply source-versioned catalog concepts. Dated official policy references enter retrieval separately. There is no invented capacity and no scraping of private profiles.

**Why are recommendations not assignments?** A public listing can be real while its available seats or participation in a specific round are unknown. Recommendations explain fit and preserve an external application link. Assignment requires a confirmed round, seats, consent, rankings, verified mandatory evidence and approved rules. An internal published allocation is still not an official offer.

**How does résumé evidence become a canonical skill?** Parse PDF pages or DOCX sections. Match exact canonical names/aliases with boundaries and ambiguity checks, or validate structured LLM claims. The quoted excerpt must occur on the stated page and support the claim. Store the canonical ID, excerpt, source, page/section, context and verification state. Related semantic concepts do not become exact aliases or verified skills. Qualifications receive authorized review.

**What makes this agentic?** In live mode one model chooses among a small typed tool set based on the current case. The graph can inspect evidence, resolve aliases, retrieve policy or request human review. Tools and deterministic gates constrain what is possible. The choices and outcomes are logged, and the graph can interrupt/resume durably. It is not just a linear chain or an LLM prompt that pretends to assign seats. Fixture mode is a reproducible branching harness, explicitly not proof of live model agency.

**What is LangGraph storing?** Case/draft references, bounded tool selections/results, counters and workflow state keyed by a persistent thread ID. PostgreSQL stores checkpoints. Raw résumé documents, private pages and hidden model reasoning stay out. Resume sends `Command(resume=...)` on the same thread after authorized review; creating a new thread would not demonstrate resumption.

**Can the LLM change a policy or publish?** No. Those capabilities are not tools. Policy configuration requires admin creation/approval; the solver runs in deterministic admin-authorized application code. Draft approval is tied to a digest and policy version; publication is a separate restricted endpoint. The evidence gate runs even if a model selects an inappropriate allowed tool.

**How is policy RAG implemented?** A selected configuration links explanatory document IDs. PostgreSQL full-text search ranks matching passages; pgvector ranks MiniLM cosine similarity. Reciprocal rank fusion sums `1/(60+rank)` across the lists. All methods share the document-version filter. The answer is a conservative supporting quote with section/version/date/URL, or an explicit insufficiency message. Retrieved text cannot become solver code or policy rules.

**What is Recall@5?** For a labelled answerable question, relevant passages retrieved among the top five divided by the number of labelled relevant passages. Average over the same answerable questions for all three methods. No-answer cases have no recall denominator, so evaluate their abstention separately. Relevant retrieval does not prove the answer is supported; inspect citations against supporting labels as an additional measure.

**What did the actual retrieval evaluation show?** Read `retrieval-results.json`. It uses 14 questions over ten passages in one historical public reference. The measured run yielded keyword Recall@5 .333, vector 1.0 and hybrid 1.0. This small corpus and author labels limit generalization. Some answerable questions still receive conservative abstention. Citation support and abstention are reported separately, and final recorded results are authoritative if the corpus or gate changes.

**Why CP-SAT rather than the LLM?** Hard capacities, one assignment per applicant, ranked-choice membership and explicit policy minimums are combinatorial constraints with deterministic checks. A language model does not provide those guarantees. CP-SAT first maximizes placement count, then fixes that count and improves quality/preference utility. FEASIBLE is not advertised as OPTIMAL; infeasible settings are not silently relaxed.

**How are missing data and equity handled?** Unavailable score components are omitted and active 35:25:15:15 weights renormalized. Unknown capacity is never replaced by a number. Demographic attributes stay out of merit and embeddings; only explicit separate equity/group constraints use them. No official quota values are invented. Rejecting an excerpt is not evidence that a qualification is not held.

**How do you independently verify a solver result?** Rebuild eligible ranked pairs from the exact snapshot and recompute applicant uniqueness, confirmed seat capacities, eligibility, preferences and hard minimums. Before approval/publication also check the current revision, policy approval/version and stored digest. The admin explicitly approves that exact draft. Retrying publication preserves the same timestamp/outcome rather than creating duplicates.

**What is not evaluated yet?** Real authorized résumé precision/recall and real confirmed-capacity allocation require participant/employer data not supplied here. Live LLM extraction/tool calling requires a configured capable provider and was not run. The separate fixture verification proves workflow behavior and real PostgreSQL checkpoint persistence, not real placements or improved acceptance. No national-scale throughput or causal fairness claim is made.

**What would production add?** Verified identity/employer authority, stronger consent/retention controls, audited policy approval governance, qualification equivalence rules, pagination/jobs at larger scale, independent annotators and larger evaluation corpora, calibrated support/entailment checks, operational monitoring, and reviewed security/deployment controls. These are outside the demonstrated academic scope.
